# ZyXEL Keenetic Extra II (`ki_rb`) — диагностика bootloop и подготовка исправления

## Статус на 2026-11-01

**Исправленный прошиваемый образ НЕ создан; исходный BIN прошивать повторно нельзя.**

Исследован `Keenetic_ExtraII_5.1.8_ki_rb_final.bin`, SHA-256:
`bac3342f7c4b4767bc8ad53195e679014d43216abf7ec76af45370f3eb69e67e`.

### Доказано непосредственно из бинарного образа

- uImage Linux/MIPS, имя `ki_rb`, LZMA, корректные CRC заголовка и сжатого ядра.
- SquashFS v4, XZ, смещение `0x170000`, размер данных FS 6 276 628 байт, 616 inode.
- Полное чтение таблиц inode/каталогов без ошибок. НЕТ `/init`, `/sbin/init`, `/bin`, `/sbin`, BusyBox и `ndm`-исполняемого файла.
- Есть отдельные приложения, библиотеки, прошивки драйверов, но нет минимального штатного userspace.
- В загрузочном образе отсутствует строка `TLV.NDM`, используемая `unpack.sh` SDK 5.01 для распознавания firmware.
- В конце образа присутствует заглушка версии `ki_rb 0.00.A.0.0-0`.

Отсутствие пользователей PID 1 — наиболее вероятное объяснение bootloop. Уточнить окончательную причину можно через UART-лог загрузки. Нет доказательств, что сами Wi-Fi-драйверы виновны.

### Проверенные источники

1. Исходный SDK Keenetic: https://github.com/keenetic/keenetic-sdk ; тег https://github.com/keenetic/keenetic-sdk/tree/5.01.C.8.0-2
2. В `target/linux/mt7628` официального SDK **нет профиля `ki_rb`**, хотя там есть профили KN-1713 и других моделей; изменение имени файла KN-1713 не создаёт поддержку старой Extra II.
3. Архив официальных оригинальных прошивок и Recovery именно **ZyXEL Keenetic Extra II**: https://archive.keenetic.ru/articles/115000129945.html
4. Разбор платформы: https://openwrt.org/toh/hwdata/zyxel/zyxel_keenetic_extra_ii

### Что необходимо для новой 5.x сборки

- Получить заведомо исправный `ki_rb` образ целиком (с работающей версией 4.03 или 3.05) для переноса board config/загрузочных параметров, и отдельно полный 5.01-образ той же MIPS/MT7628 ABI для изучения нового userspace.
- Явно разработать/проверить профиль `ki_rb`, включая SPI разметку, 2.4/5 ГГц EEPROM, GPIO, Ethernet switch, flash size / Dual Image.
- Заполнить базовую систему: настоящий init/PID 1, динамический загрузчик, `ndm`, зависимости, сеть, Wi-Fi и корректный components.xml.
- Запустить сборку SDK 5.01.C.8.0-2 в чистой Debian/Ubuntu-среде и отклонять неполные образы до прошивки.
- Проверить полученную сборку статически, затем через UART/QEMU-семейство MIPS, где это позволяет эмуляция; аппаратно-зависимое поведение — только на реальном Extra II.

### Хранение без GitHub Actions artifact storage

Исходники, конфиги и отчёты — в Git-репозитории `Pokateli/Temp`; большие образы, если будут опубликованы, — в GitHub Releases, а **не** `actions/upload-artifact`. Входной дефектный BIN в этот набор намеренно не включён, чтобы не распространять прошивку с bootloop.

## Запуск аудита

```sh
python3 audit_image.py /path/to/firmware.bin --json
```

Программа использует только стандартную библиотеку Python, читает файловую систему без распаковки на диск, не модифицирует прошивку. Возвращает код `1` при критических структурных дефектах. Это предохранитель от заведомо неполной сборки, но не гарантия загрузки образа со статусом `STRUCTURE_OK_NOT_BOOT_TESTED`.
